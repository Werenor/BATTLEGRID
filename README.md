# BATTLEGRID

四艘舰船，一片未知海域，一次一炮。

BATTLEGRID 是为 **eraAzurLane** 制作的经典海战棋小游戏，使用 EraElectron 运行。实验版已完工，当前支持独立启动；接入 eraAzurLane 属于后续工作。它是一项可反复游玩的对弈活动，没有独立技能和闯关流程。

## 启动

打开 EraElectron，在菜单中选择“游戏 → 打开游戏”，选择 BATTLEGRID 项目目录。

EraElectron 需要单独安装，仓库不包含引擎可执行文件。下载或克隆仓库后，选择包含 `csv/` 和 `ere/` 的项目根目录即可。存档和试玩日志在运行时自动生成。

游戏由 `ere/main.js` 启动，窗口标题为 `BATTLEGRID`。游玩不需要运行 npm 命令，也不需要安装额外依赖。

## 玩法与操作

双方各有一张 **8×8** 棋盘，以及长度为 **4、3、3、2** 的四艘舰船。玩家先布置自己的舰队，再与 AI 轮流盲打对方棋盘；先击沉对方全部舰船的一方获胜。

- 舰船必须横向或纵向连续放置，不能重叠、越界。
- 舰船允许任意相邻。首尾相接、平行贴靠、斜角相邻都合法，也可以用于迷惑对手。
- 每回合只能开火一次，命中后不追加行动。
- 击沉时，只有这艘船的全部格子变红，不揭示周围是否有船。

### 布舰

点击第一个端点后，白色位置表示合法终点；点击终点完成当前舰船的放置。点击已放置的舰船可以重新放置。“取消放置”会撤销当前操作，移动舰船时会恢复原位置；“清空全部”重新布置整支舰队。

布舰界面的先手按钮循环选择“玩家 / 对手 / 随机”。全部舰船放好后，点击“确认布舰”开始对局。

### 开火

对局中，我方棋盘在左，敌方棋盘在右。点击敌方的未知格开火。

回合自动推进：先显示玩家战果，短暂停留，再显示 AI 思考与战果，最后恢复玩家操作。默认玩家战果停留 750ms、AI 思考等待 1000ms、AI 战果停留 750ms；目标分析所需的计算时间另计。无需点击结束回合按钮。

“认输并退出”需要再次确认。终局可以查看复盘，或返回开局设置开始新的一局。

### 棋盘颜色

| 颜色 | 含义 |
|---|---|
| 灰色 | 未知、尚未攻击 |
| 蓝色 `×` | 未命中 |
| 黄色 `◆` | 命中，但所属舰船尚未击沉 |
| 红色 `■` | 已击沉舰船 |
| 绿色 `■` | 己方尚未受损的舰船格 |
| 白色 | 布舰时的合法终点 |

## AI 设置

开局可分别设置 AI 的**布局能力**、**攻击能力**和**攻击偏好**。能力分为“较弱 / 熟练 / 高手”，默认均为熟练。攻守能力最多相差一级；选择跨度过大的组合时，另一项会自动调整为熟练。

攻击偏好默认随机，在玩家布舰前抽取并公开，整局保持固定：

| 攻击偏好 | 主要关注 |
|---|---|
| 进攻型 | 命中概率 |
| 策略型 | 击沉机会与伤船完成进度 |
| 信息型 | 开火后能排除多少可能布局 |

三种类型都优先追击伤船，并处理高概率收尾机会。能力等级影响从候选中选择高质量行动的稳定程度。

布局倾向由系统暗中随机，包含均衡、分散、集中、沿边和角落。对局中不公开，结束后才揭晓。

AI 只根据攻击者能够看到的反馈推理。相邻黄色格可能属于同一艘船，也可能属于不同的贴靠舰船；推理会保留这些归属歧义。内部评价图不向玩家显示。

## 行动评价与复盘

双方战报前会出现彩色评价符号，正文保持白色：

| 符号 | 颜色 | 含义 |
|---|---|---|
| `i` | 绿色 | 正常、合理 |
| `!` | 蓝色 | 好棋 |
| `!!` | 青绿色 | 妙手 |
| `?!` | 黄色 | 不精确 |
| `?` | 橙色 | 失误 |
| `??` | 红色 | 严重失误 |

评价依据**开炮前的公开信息**，双方使用同一标准。打空不等于失误，蒙中也不等于好棋。

- 尚未发现舰船时，只要目标位置仍可能容纳剩余舰船，探索记为 `i`。
- 普通追击、相近方向的试探和沿已明确船身的连续攻击，通常记为 `i`。
- 具有比较优势的追击、有价值的搜索试探、及时收尾，可以获得 `!`；不会把一串普通连打逐炮奖励。
- 普通次优选择最多标为 `?!`。`? / ??` 留给明显错过收尾，或攻击已经被公开情报排除的位置。
- `!!` 使用更严格的启发式条件，评价目标是辨认歧义局面中不易发现的高价值行动。

终局点击“查看复盘”，按回合翻页查看双方行动、质量分、最佳分、决策损失、推荐位置和解释。推荐位置仅在终局复盘显示。质量分是行动收益指标，不是胜率。

## 分析方式

AI 选点与行动评价共享对同一公开局面的分析：

1. 在预算内完整枚举所有合法舰队组合，范围不限于最后一艘船。
2. 去除相同长度舰船交换标签造成的重复组合。
3. 若无法完成枚举，丢弃未完成的枚举前缀，改用确定性采样。
4. 计算命中、击沉及信息价值，并缓存分析结果。

默认枚举预算为 20000 个搜索节点、5000 种布局；采样最多取得 360 个布局，总搜索预算为 120000 个节点。采样估算会给评分保留误差容差，少于 30 个样本时暂不评价；精确枚举不受这个最低样本数量限制。复盘会注明采用完整枚举还是采样。

统一评价采用绝对收益差，避免将微小概率差放大成严重失误。采样容差是保守的启发式处理，不是严格的统计置信区间。

## 日志与自动对战

### 引擎试玩日志

日志通过引擎的 `era.saveGlobal()` 保存到 `sav/global.sav`，公共变量 `0` 存放 JSON 格式的对局档案，保留最近 20 局。逐炮记录，未完成的对局也会保留已发生的行动。

记录包括开局配置、双方实际布局、每炮之前的公开知识、AI 候选与选点、战果、评价和终局结果。实际布局只供离线诊断，选点和评分不读取它。

引擎禁止游戏脚本直接加载 `fs`、`path` 等 Node.js 内置库，因此文件日志适配器只用于命令行脚本，不进入游戏运行依赖。

### 命令行验证

在项目目录中，使用 Node.js 运行：

```powershell
npm test
node scripts/simulate.js
node scripts/rating-experiment.js
```

- `npm test`：验证规则、回合顺序、AI 推理、评价、复盘及日志。
- `simulate.js`：运行九场完整自动对局，覆盖三种攻击偏好及偏边、平行贴靠、首尾贴靠布局。
- `rating-experiment.js`：运行 36 场配对对局，交换先手，比较好评数量、每炮好评率与胜负。

命令行逐炮日志保存在 `logs/match-*.jsonl`；汇总分别写入 `logs/simulation-summary.json` 和 `logs/rating-experiment.json`。重复运行会生成新对局日志，并覆盖对应汇总文件。

自动对战双方由机器人操作，结果不代表人类胜率。评价实验用于观察好评与胜负的关联；收尾奖励本身也与击沉数量相关，不能单凭总体相关性证明评分完全合理。

## 项目结构与接入

```text
BATTLEGRID/
  csv/       引擎静态数据与配置
  ere/       独立启动入口和 EraElectron SDK
  src/       棋盘、规则、AI、会话、评价、日志与页面
  tests/     回归测试
  scripts/   命令行模拟和文件日志适配器
  sav/       引擎公共存档与试玩日志
  logs/      命令行对局日志和实验汇总
```

`src/era-page.js` 导出 `createEraPage(era, options)`。接入方注入 EraElectron 对象，调用返回的异步页面函数；页面结束时返回胜负、回合数及双方命中、开炮、击沉统计。规则层和 AI 不依赖页面 API。

```js
const { createEraPage } = require('./src/era-page');

const pageBattlegrid = createEraPage(era, {
  aiProfile: {
    placement: { skill: 'competent', style: 'random' },
    targeting: { skill: 'competent', style: 'random' },
  },
  firstPlayerChoice: 'player',
  playerResultDelay: 750,
  aiDelay: 1000,
  aiResultDelay: 750,
});

const result = await pageBattlegrid();
```

独立版使用 `csv/Global.csv` 中的公共变量 `0` 保存日志。接入 eraAzurLane 时，需要为日志重新分配公共变量，避免覆盖宿主游戏的数据；同时使用宿主已有的 SDK 和页面入口。

本版作为实验项目的完工基准保留。后续调整以具体试玩反例和日志为依据。
